# Riders bug-class tracker

Running log of failure *classes* the Riders stack has been hardened against.
One row per class — not per incident. A class stays open until:

1. invariant is defined,
2. smallest server-aligned fix landed,
3. whole-class regression tests landed (not just the exact transcript),
4. live canary ran green on current main.

> **Workflow gate**: we do not widen QA while any class below has
> `status != closed`. Every new bug must be triaged into a class first
> — either an existing one (then it's recurrence evidence) or a new one
> (then it needs invariant + regression + canary before we move on).

## Gating rule

Before widening QA to new scenarios, every class in this table must have
`status=closed` + `regression` row non-empty + `live canary` row showing a
passing run on current main. A new bug that reproduces a class already
marked closed increments the `recurrence seen` counter AND reopens the
class until a stronger invariant lands.

## Phase C eval corpus (2026-04-21)

The `[drift/get-price-bypass]` and `[structured-output/proposer]` emits
above are individually useful on a single canary run, but a single run
is a sample of one. The Phase C corpus (`scripts/eval-corpus/`) is the
hybrid harness that turns those emits into N-run aggregates across a
fixed set of blocker + happy-path cases, so we can measure the
promotion gates declared in the observability-signals table without
cherry-picking runs.

- **Cases** live in `scripts/eval-corpus/cases.mjs`. Each case names
  the class it exercises (Class 15, Class 16, happy path, informational
  guard) and lists the turns to post, with optional per-turn advisory
  asserts over `turn_kind`, `outcome`, `present`, `schema_valid`, and
  `plan_vs_fire`.
- **Live cases** post through the real webhook via
  `live-riders-harness.mjs` and scrape the gateway journal for the two
  Phase A/D emits between turns. Same `resetLiveConversationState` path
  the individual canaries use, so no extra state mutation.
- **Unit cases** run the schema-validator contract in-process
  (`unit-schema-contract.mjs`, 16 checks). Hard-fail: a broken
  in-repo contract exits the runner non-zero.
- **Hybrid rollup** in `runner.mjs` emits a per-case + corpus-level
  rollup with turn_kind × outcome, plan_vs_fire distribution, proposer
  present/schema-valid rates, `get_price` fired / bypass rates, and
  case pass-rates. Output goes to
  `reports/eval-corpus/<run_id>/{raw.jsonl,report.json,report.md}`.

Usage:

```bash
npx tsx scripts/eval-corpus/runner.mjs --n 5                         # full sweep
npx tsx scripts/eval-corpus/runner.mjs --cases C15-paired-ambiguous-city --n 5
npx tsx scripts/eval-corpus/runner.mjs --unit-only --n 1             # ~3s contract check
```
